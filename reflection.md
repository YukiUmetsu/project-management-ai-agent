# Reflection

## Improvements I made

1. API call error handling and logging
   - I created a base Agent class and implemented respond function to call OpenAI API with error handling.
   - In case of api call failure, all agents will retry up to specified amount of times with jitter and bounce.
   - All the agent class inherit the Agent class, so every agent will have the error handling by default.
2. State and Context management
   - Program Manager and Developer agents were not utilizing user stories generated by Product Manager agent.
   - In order to pass down the user stories and other product information, I created state object, then passed down as context.
   - Thanks to this, developer agent was able to create development tasks more accurately.

## Strength

1. It separates responsibilities across specialized agents, such as product management, program management, and development engineering, which improves modularity and makes each agent easier to evaluate independently.
2. The use of evaluation agents also adds a feedback loop that can detect weak responses and request corrections before passing results downstream.
3. Routing allows the workflow to select an agent based on the user’s request instead of always running every agent.

## Limitations

One limitation is that semantic routing alone does not understand dependencies between agents. For example, a request for development tasks may be routed directly to the development engineer even though that agent depends on user stories and product features produced by earlier agents. This can result in incomplete context or lower-quality outputs. The workflow is also vulnerable to cascading failures because an incorrect or missing output from one agent can affect every downstream agent.

## Further improvement ideas

1. One specific improvement would be to add dependency-aware workflow orchestration. The router could first determine the final requested artifact, such as development tasks, and then a dependency graph could automatically determine which prerequisite agents must run. For example, a development-task request would execute Product Manager → Program Manager → Development Engineer, passing each validated output to the next agent. This would make routing more reliable while preserving the modular agent design.
2. Using pytest to run tests. Pytest advantages:
   - Automatically discovers and runs tests.
   - Better assertion/error messages.
   - Easy to run all tests with one command.
   - Supports fixtures and parameterized tests.
   - Easier CI/CD integration.
   - Better for regression testing as the project grows.
